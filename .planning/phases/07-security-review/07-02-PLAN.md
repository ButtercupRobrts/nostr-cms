# Phase 07-02: Security remediation batch

Upstream of findings in `07-01-FINDINGS.md`. Scope: four small changes, one upstream PR each for 2–4 grouping, deployed to buttercup first.

## Decisions (from discussion)

- Nsec gate: **default OFF in production builds**, override via `VITE_ENABLE_NSEC_LOGIN=true` (dev `.env.local` keeps it on)
- Blossom fallback: **buttercup = hard error**, upstream = prominent warning toast (compat split)
- Batch ships buttercup-first like phases 05/06, then packaged upstream

## Task 1 — Gate nsec login behind env flag (~30 lines)

**Files:** `src/components/auth/LoginDialog.tsx`, `src/components/auth/SignupDialog.tsx`, `.env.example`

- Read flag once: `const NSEC_ENABLED = import.meta.env.VITE_ENABLE_NSEC_LOGIN === 'true'` — centralize in `src/lib/relay.ts` next to other env helpers (they already live there).
- `LoginDialog`: when disabled, key tab hidden; if extension present it stays primary, bunker tab stays. If BOTH extension absent AND nsec disabled → bunker becomes the default tab. `.txt` file input is inside the key tab → disappears with it.
- `SignupDialog`: nsec-download step gated; extension users get npub-only display + "copy npub" (no key material download).
- **Documented honestly as policy control, not sandbox** — nostrify's machinery remains bundled; the flag removes the UI surface. Comment in code says so.
- `.env.example`: document the flag.

## Task 2 — sha256-verify Blossom page fetches (M1)

**File:** `src/pages/StaticPage.tsx` (`fetchFromBlossom`)

- After `response.text()`, hash bytes with `sha256` from `@noble/hashes/sha256` (already a dep — used by `streamUpload`) and compare hex to the event's `sha256` tag.
- Mismatch → skip that server, try the next; all fail → fall back to `pageEvent.content` (existing fallback path, unchanged).
- Same treatment applied to any other by-hash fetch — grep for `${server}${sha` patterns before declaring done.

## Task 3 — Blossom fallback hardening (M2)

**Files:** `src/hooks/useUploadFile.ts`, shared blossom-relay derivation

- Empty `blossomRelays` → **buttercup behavior**: throw `Error('No Blossom server configured')` (surfaces as existing error toast in callers).
- Upstream PR variant: same but warning toast + proceed to primal.net fallback — split decided at PR packaging (keep diff minimal; the throw version goes upstream with a flag? No — upstream gets warn-proceed, buttercup gets throw. Implementation: single function `getUploadServers()` returning `{servers, missing: boolean}` used by both behaviors).

## Task 4 — dompurify bump (L1)

- `npm audit fix` scoped to dompurify (or manual bump to ≥3.4.16, pinning exact version per repo convention). We don't use `IN_PLACE` mode so it's defense-hygiene, not reactive.
