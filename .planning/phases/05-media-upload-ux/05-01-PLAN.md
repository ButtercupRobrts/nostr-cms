Verified facts (meetup-space working tree, no .git):

**Existing dropzone (source of truth for extraction)** — `AdminMedia.tsx` `UploadMediaSection`:
- `isDragging` state + `dragCounter` ref (lines 849-850). The counter is REQUIRED: the dropzone has child elements (icon div, text), so dragenter/dragleave fire on every child transition — a boolean toggles flicker.
- `handleDragEnter` increments counter, sets isDragging only when `e.dataTransfer.types.includes('Files')` (856-861).
- `handleDragLeave` decrements, clears at <=0 (863-871). `handleDragOver` just preventDefaults — required for drop to fire (873-877).
- `handleDrop` resets counter+state, guards `if (isUploading) return`, passes `e.dataTransfer.files` to `handleFiles` (879-889).
- Window `dragend`/`drop` reset effect (892-903) — clears stuck isDragging when user drags out of the window without dropping.
- Markup (1259-1296): `isDragging ? "border-primary bg-primary/10"` class, `onClick` guarded by `!isDragging`, label switches "Drop files here" / "Browse or drag & drop".

**Target** — `MediaSelectorDialog.tsx`:
- `handleUpload(e: ChangeEvent)` (198-249) is bound directly to `<input onChange>` and reads `e.target.files` — must be split into `handleFiles(files: FileList)` core + thin input wrapper, same pattern as AdminMedia (905-1057).
- Upload loop (214-231): `streamUpload` for `video/*`, `BlossomUploader` (multi-relay `Promise.any`) for everything else; AggregateError unwrap at 241-243; success → toast + `invalidateQueries(['blossom-blobs'])` + `setActiveTab('browse')`. All unchanged.
- Dropzone markup (502-529) already looks like a dropzone (dashed, hover states) but only has onClick.

**Parity gaps to close while in there:**
- `accept="image/*,video/*"` does NOT apply to drops — dropped files bypass the input filter. AdminNotes' drop handler filters `image/|video/` MIME (AdminNotes.tsx:691-692); AdminMedia's doesn't. Dialog should filter + toast if nothing usable was dropped.
- `stripImageMetadata` (mediaProcessing.ts:105): call for `image/*` only. GIF returns `reason:'gif'` unstripped — caller must warn; dialog has no status line so use a toast (AdminNotes.tsx:615-620 pattern). Never call it on videos — `loadImage` would fail.

**Non-issues (verified, don't over-engineer for):**
- Radix Dialog does not interfere with native DnD events; dropzone inside TabsContent works fine.
- `pointer-events-none` when `isUploading` already blocks drops visually; hook still takes a `disabled` flag for correctness.
- Post-upload `setActiveTab('browse')` is desired for drops too (same flow).

**Verification gate:** `npm test` = `tsc --noEmit && eslint && vitest run && vite build` (package.json:10). Prior known-good: 27 tests, 6 files, 0 tsc errors (STATE.md).
