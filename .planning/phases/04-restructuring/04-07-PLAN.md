<objective>
Remove the nsec (secret key) login path from the bundled dashboard UI — NIP-07 extension only — and vendor the nostr-tools bundle instead of loading it unsigned from unpkg.

Purpose: bitkarrot's review flagged NostrLogin.js as security-sensitive (nsec input in browser + hand-rolled signing). Deleting the nsec path eliminates the need for that audit entirely. The vendored bundle removes the unsigned-CDN-script-on-auth-page surface. This also simplifies 04-03 — `window.nostr.signEvent` becomes always a real signer that prompts the user.
Output: one small PR against zeabur-dashboard. NIP-46 `bunker://` support is a *separate follow-up* (not in this PR).
</objective>

<context>
Verified facts (zeabur-dashboard @ a30fb61):
- nsec path keeps `_privkeyHex` in module memory (not localStorage) but installs a `window.nostr` shim whose `signEvent` signs silently — XSS → unlimited signatures.
- `nostr-tools@2.10.4` loaded from unpkg.com with NO SRI integrity attr in dashboard.html:7 and convert.html:8.
- `templates/dashboard_view.html` references `NostrTools` (lines ~378, 387) but never loads the script — latent bug fixed by the vendored include.
- `convert.html` login is cosmetic only (autofills npub/username); `dashboard.html` is the real gate.
- `hexToBytes`/`bytesToHex`/`sha256Hex`/`_nativeWindowNostr` are used ONLY by the nsec path — all become dead.
- `setup/blossom-upload.go` accepts nsec via terminal prompt — CLI tool, out of scope.
- Only nsec refs in repo: NostrLogin.js. No docs updates needed.
</context>
